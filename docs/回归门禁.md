# 回归门禁

## 现在挡着什么

46 条测试，全部是「某个已经发生过的 bug 修好之后该有的行为」，不是对现状的描述。

- `tests/test_review_fixes.py` 17 条 —— 2026-11-05 那轮 P0 修复
- `tests/test_review_2026_11.py` 29 条 —— 2026-11-11 全面 review 的 20 条，加本轮示例编号隔离 6 条、引用识别 3 条

跑一遍 0.3 秒，纯内存库 + 临时目录，不碰 `data/guanlan.db`。

## 三种跑法

```
tools\run_tests.cmd                          # 一键，窗口里直接看结果
python -m unittest discover -s tests -v      # 等价的裸命令
git hook run pre-commit                      # 单独跑一次门禁（不提交）
```

## 提交前自动跑

一次性安装（只改本仓库的 `core.hooksPath`，不动全局配置）：

```
.githooks\install.cmd
```

之后每次 `git commit` 都会先跑整套测试。失败时提交被挡下，`tail` 打出失败用例。
真需要绕过（改错别字、临时存档）：

```
GL_SKIP_TESTS=1 git commit -m "..."
```

卸载：

```
git config --unset core.hooksPath
```

机器上没有 python 时，钩子打一行提示然后放行，不会把人锁在仓库外面。

## 写新测试的规矩

先让它在修复前的代码上失败（或者确认它断言的是修复后的行为），再让它变绿。
否则测的是「现在是怎样」，拦不住任何东西 —— 上一轮 20 条里有 18 条做过这个反向验证。
