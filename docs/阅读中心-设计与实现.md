## 1. 定位与布局重构

### 1.1 为什么要改布局

原应用是「单侧栏 + `.main` 固定 `padding: 30px 40px; max-width: 1240px`」的卡片流。阅读是长文沉浸式行为，卡片流留白和多列网格都不适用。因此把「阅读中心」做成与「收存」**平级的大板块**，而不是塞进工具菜单里的一项：

- 侧栏顶部新增 `sect-switch`（收存 / 阅读中心），点击切换的是**整套二级导航**（`#nav-vault` ↔ `#nav-reading`），不是加一个菜单项。
- 阅读中心激活时 `body.rc-active` → `.main { padding: 0; max-width: none }`，把整块主区交给阅读中心自己布局。
- 书架类页面走 `.rc-view`（宽版统计条 + 筛选 + 自适应卡片栅格）。
- 阅读器走 `.rc-reader`：整屏 `height:100vh`，`grid-template-columns: 244px minmax(0,1fr) 316px`，左（目录/书签）、中（正文）、右（标注/笔记/AI/关联）三栏各自滚动。
- `<900px` 时左右栏转为抽屉（顶栏 ☰ / ▤ 切换）；`<720px` 手机底栏扩到 8 项并压缩字号，无横向溢出（已实测 390px 宽）。
- 第五种高亮色 `violet`（联想）同时补进 `server.py`、`app.js`、`reading.css`，收存的正文批注也能用。

### 1.2 路由

| Hash | 视图 |
|---|---|
| `#/reading` | 书架总览（统计 / 继续阅读 / 筛选 / 卡片） |
| `#/reading/shelf/{id\|none\|all}` | 指定书架 |
| `#/reading/book/{clip_id}` | 沉浸式阅读器 |
| `#/reading/notes` | 笔记沉淀 |
| `#/reading/search` | 全文检索 |
| `#/reading/archive` | 知识库归档 / 关系网 |
| `#/reading/stats` | 阅读统计热力图 |

`app.js` 暴露 `window.GL`（api / post / 正文渲染 / 标注锚定 / 对话框 / `addRoute`），`reading.js` 复用而不是复制；首屏 `route()` 改为 `setTimeout(route, 0)`，保证独立脚本先注册完路由，刷新在 `#/reading` 上不会被弹回收存。

## 3. 数据模型与关联方式

### 3.1 一条原则：不另起内容库

**一份阅读资料 = 一条 `clips`**。`clips` 仍是原件、标签、板块、全库检索、知识卡、AI 语料的唯一事实源；`reading_items` 只挂「阅读态」扩展。这样批注、摘录、笔记天然能被收存 / 检索 / 问 / 洞察看到，双向互动不需要同步两份数据。

### 3.2 表与关系

```
clips ──1:1── reading_items ──N:1── reading_shelves ──?── boards
  │                 │
  │                 ├── reading_bookmarks   (书签)
  │                 ├── reading_notes       (Markdown 笔记 / 摘录)
  │                 ├── reading_sessions    (每日阅读会话 → 热力图)
  │                 └── reading_links       (双向引用边)
  ├── clip_annotations  (高亮/批注：与收存详情页共用，字符偏移锚在 clips.content_text)
  ├── clip_notes / verdicts / ai_outputs / clip_images ...（原有能力全部保留）
  └── reading_fts (FTS5 虚表：kind, clip_id, ref_id, offset, title, body)

reading_links 的 (src_kind, src_id) / (dst_kind, dst_id) 是通用多态引用：
  kind ∈ annotation | bookmark | note | excerpt | clip | claim | board | ai_output | verdict
  id   统一字符串（claim 用 C-2026-0001 这类 code）
  每次建边自动写反向边 → 从知识卡也能回溯到批注
```

| 表 | 关键字段 | 口径 |
|---|---|---|
| `reading_items` | `clip_id` PK/FK, `kind`, `format`, `shelf_id`, `doc_text`, `chapters`, `position`, `position_unit`, `progress`, `read_seconds`, `status` | `position_unit=char` 用于书籍/文档，`second` 用于音视频；`doc_text` 是**持久化副本** |
| `reading_shelves` | `name`, `parent_id`, `board_id` | 阅读中心自己的分类树；`board_id` 是归档到知识库的默认落位 |
| `reading_bookmarks` | `offset`, `time_sec`, `chapter_id`, `label` | 正文按字符偏移、音视频按秒 |
| `reading_notes` | `content_md`, `source_quote`, `source_annotation_id`, `kind`, `archived_clip_id` | 归档后回填生成的 clip id，防止重复归档 |
| `reading_links` | `src_kind/src_id`, `dst_kind/dst_id`, `relation`, `clip_id` | `UNIQUE` 防重复；`refs/cites/supports/derived_from/belongs_to` |
| `reading_sessions` | `day`, `clip_id`, `seconds`, `chars` | `UNIQUE(day, clip_id)` + UPSERT，热力图数据源 |
| `reading_fts` | `kind`, `clip_id`, `ref_id`, `offset`, `title`, `body` | `tokenize='trigram'` 中文子串可用；按 `clip_id` 整段重建 |

### 3.3 三个关键工程决策

1. **正文自愈（R2）**：`server.init_db()` 每次启动会执行 `UPDATE clips SET content_text='' WHERE source_type='file'`，字符偏移批注会失锚。因此阅读中心把结构化正文另存 `reading_items.doc_text`，并在 `init_db()` 里从它回填 `clips.content_text`；`GET /api/reading/book/{id}` 也会调用 `ensure_text()` 再校一次。重启后批注不漂。
2. **标注锚点复用**：阅读器的高亮直接写 `clip_annotations`（`start_offset/end_offset/quote/prefix/suffix`），前端复用 `prepareAnnotations()` 的重锚定逻辑。阅读中心里做的批注，回到 `#/c/{id}` 详情页立刻可见，反之亦然。
3. **FTS5 的坑**：`MATCH` 左侧必须是**表名**而不是别名（`reading_fts MATCH ?`，`f MATCH ?` 会报 `no such column: f`）；`trigram` 对 1–2 字词无三元组，所以短词走 `LIKE` 扫源表兜底，且兜底也按章给跳转坐标。

## 4. 关键交互流程

### 4.1 导入 → 分章 → 建索引
```
拖放/选择文件 → POST /api/clips/upload?name=…（原始二进制，最大 200MB）
  → register_file() 去重 + 落盘 data/uploads + 抽正文
  → POST /api/reading/items {clip_id, shelf_id}
      → 按后缀分类（book/doc/audio/video）
      → parse_material(): EPUB 走 container.xml→OPF→spine+nav/ncx；
        PDF 走 pypdf 页文字+大纲；文档走标题行/段落切章
      → _build() 生成 doc_text 与绝对字符偏移 chapters
      → 写 reading_items + 回填 clips.content_text + reindex FTS
```
音视频没有文字层时保留原件与播放器，可后续粘贴「文字稿」重建目录/高亮/检索。

### 4.2 阅读 → 高亮/批注 → 书签
```
打开书 → GET /api/reading/book/{id}（一次拿全：正文/目录/标注/书签/笔记/关联/进度/板块/正典）
  → 按 item.position 恢复章节与滚动位置（续读）
选中文字 → 浮动工具条（五色 + 批注 + 摘录 + 书签 + 问 AI + 复制）
  → POST /api/annotations/{cid}（复用原接口） → POST /api/reading/reindex 刷新索引
目录点击 / 上·下章 / 书签定位 → 切章渲染 + 保存进度
滚动/播放每 15s → POST /api/reading/progress/{cid}（写 position/progress + UPSERT 当日会话）
```
正文按章渲染（不是整本一次性塞进 DOM），段落 `data-a-start/a-end` 保留**绝对**正文坐标，选区经 `offsetInBlock()` 换算后落库，所以跨章标注也准。

### 4.3 全文检索 → 跳回原位置
```
输入 → GET /api/reading/search?q=&scope=&shelf=
  → FTS5 MATCH（≥3 字）或 LIKE 兜底（短词）
  → 命中 = {kind, clip_id, chapter_id, offset, snippet, score}
点击结果 → sessionStorage.gl_read_jump → #/reading/book/{cid}
  → 切到 chapter_id、滚动到含 offset 的段落、闪光定位
```
`scope` 可限定 `正文 / 批注 / 笔记 / 书签 / 卡片`。

### 4.4 笔记沉淀 → 知识库归档 → 双向引用
```
批注「存笔记」/选区「摘录成笔记」/右栏「新建笔记」
  → POST /api/reading/notes（Markdown，可带 source_quote 与 source_annotation_id）
「汇入知识库」→ POST /api/reading/archive
  → 生成一条新 clips（source_type=text, channel=阅读摘录, 带上书名出处）
  → 写 reading_links 正反两条边（annotation/note ⇄ clip）
  → 回填 reading_notes.archived_clip_id，重排 FTS
「引用」→ POST /api/reading/links（可指向收存卡片 / 正典命题 / 板块）
  → 同样自动写反向边
```
从收存侧：`GET /api/reading/links?dst_kind=clip&dst_id=…` 可列出所有反向引用；`app.js` 在 `#/c/{id}` 详情页渲染完成后调用 `GLReading.decorateClip()`，在页尾追加「阅读中心 · 回溯到原文」面板，列出引用了这张卡片的批注 / 摘录 / 笔记，并提供「打开原书 ↗」直接跳回当时的阅读位置。生成的知识卡本身进全库检索，点开可回溯到原书与批注。

### 4.5 AI 伴读（WorkBuddy 账号额度）
```
右栏「AI 伴读」→ 8 个动作：总结本章 / 解释选中 / 全书提纲 / 翻译选中 /
                  提炼要点 / 思考题 / 自由提问 / 整理笔记
  → POST /api/ai/reading {clip_id, action, chapter_id, selection, question, content_md}
  → reading.api_ai_reading 组装「书名 + 全书目录 + 当前章节 + 选区 + 我的笔记」上下文
  → 调 server.ai_chat()（WB_DEFAULT → /.cloud/llm/chat/completions，stream + x-wb-webapp-access-key）
  → 返回 {text, model, quota:"WorkBuddy 账号云端额度", context:{章字数, 选区字数}}
  → 可一键「存为笔记」（kind=ai）
```
**没有新 Key、没有新账单**：和「问 / 洞察」共用同一条云数据面通道，界面明确标注额度来源与上下文范围。AI 只读当前章节与选区，不冒充用户写判断。

### 4.6 阅读统计
`reading_sessions` 按日聚合 → 17 周热力图、连续天数、累计时长/字数、类型与状态分布、读得最久的书。

### 4.7 导出
`GET /api/reading/export/{id}` 输出 Markdown：目录 + 五色高亮与批注 + 笔记（含原文摘录）+ 书签 + 关系清单，浏览器直接下载。

## 6. 多格式支持矩阵

| 类别 | 格式 | 正文 | 目录 | 阅读能力 |
|---|---|---|---|---|
| 书籍 | EPUB | OPF spine + nav/ncx 逐章 | 真实书名 / 章节标题 | 全功能 |
| 书籍 | PDF | pypdf 逐页文字层 | 优先 PDF 大纲，否则标题行 / 页组 | 全功能；扫描件可补文字稿 |
| 书籍 | TXT / MD / HTML | 原文本 / HTML 清洗 | 标题行、Markdown `#` | 全功能 |
| 书籍 | MOBI / AZW3 / FB2 / CBZ | 原件保留（无内置解析器） | 可粘贴文字稿补 | 可管理 + 文字稿接入全功能 |
| 文档 | DOCX / PPTX / XLSX / CSV / JSON | 复用 `extract_file_text()` | 标题行 | 全功能 |
| 音频 | MP3 / M4A / WAV / OGG / FLAC / AAC | 原件 + 可选文字稿 | 时间轴 | 播放器 + 秒级书签/进度 + 文字稿全功能 |
| 视频 | MP4 / MKV / WEBM / MOV / AVI | 原件 + 可选文字稿 | 时间轴 | 同上（Range 支持拖动进度条） |
| 收存 | 已有网页 / 文字 / 文件条目 | 直接纳入 | 自动分章 | 全功能 |

> 单文件上限 `GL_MAX_UPLOAD_MB`（默认 200MB）；正文抽取上限 40MB / 30 万字，超长书按章阅读不塞满 DOM。

## 8. 与 ReadAny 的设计对照

| ReadAny | 观澜阅读中心的取舍 |
|---|---|
| 8+ 格式书架、本地优先 | 同样多格式统一书架；**复用观澜已有的 clips 原件层**，不另建文件库 |
| 沉浸式阅读、字号/主题可调 | 整屏三栏 + 三种纸张 + 字号/行距/宽度可调并记忆 |
| 五色高亮 + Markdown 笔记 | 五色（重点/论据/疑问/反驳/联想）+ Markdown 笔记/摘录 |
| AI Chat（自带 Key） | **接 WorkBuddy 账号云端额度**，零配置；上下文限定当前章节 + 选区 |
| 语义检索 | 中文子串 FTS5 trigram + 短词兜底；结果带字符偏移可精确回跳（不依赖向量服务，纯本机） |
| TTS 听书 | 未做 TTS；但音频/视频资料本身可播放、按秒做书签与进度 |
| 导出 Obsidian/Notion | 导出 Markdown（含出处、批注、笔记、书签、关系清单） |
| 阅读热力图 | 17 周热力图 + 连续天数 + 累计时长/字数 |
| WebDAV/S3 同步 | 沿用观澜已有的局域网 / 云同步（阅读表随 `guanlan.db` 一起走） |
| 独立 App | **不做独立 App**，而是应用内一级大板块，批注/摘录/笔记直接进观澜知识库 |

## 9. 运维备注

- 阅读数据全部落在 `data/guanlan.db`，随原有备份 / 云同步一起走；原件在 `data/uploads`。
- `/api/reading/reindex` 不传 `clip_id` 可全量重建索引（升级解析逻辑后用）。
- 删除收存条目时会级联清理 `reading_items` 及阅读散件；反过来「移出阅读中心」只删阅读态，原件与知识卡都保留。
- 若 `GL_AI_*` 环境变量被显式设置，`ai_chat()` 会改走自定义 OpenAI 兼容端点，界面额度标注随之变为「自定义端点」；不改任何配置时默认就是 WorkBuddy 账号额度。
- 本次开发期间服务由会话内后台进程承载；**重启电脑或结束会话后，点桌面「观澜」图标即可按正常方式拉起**（桌面快捷方式指向 `launch.vbs`）。
