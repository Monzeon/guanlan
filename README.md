**自己的收存柜：把重要的东西收进来，然后能问它们。**

> 观水有术，必观其澜。——《孟子》

桌面端四个平级大板块：收存、阅读中心、圣经与事件。侧栏顶部的 2×2 切换器换的是整套导航，不是加一个菜单项。

| 板块 | 干什么 |
|---|---|
| **收存** | 左边是板块（政治、经济、文化、社会，自己加自己删）。中间一个框：贴链接 / 写一段话 / Ctrl+V 贴截图 / 拖图片或文件进来，选个板块就收进去。 |
| **阅读中心** | 主要阅读阵地：导入 PDF / EPUB / 文档 / 音视频 → 书架分类 → 分章阅读（五色高亮、批注、书签、目录跳转、进度）→ 正文与批注全文检索 → Markdown 笔记 → 一键汇入知识库并留下双向引用。AI 伴读走 WorkBuddy 账号云端额度。完整设计见 [`docs/阅读中心-设计与实现.md`](docs/阅读中心-设计与实现.md)。 |
| **事件（桌面端）** | 新建事件专题 → 关联已有收存 → 按实际发生时间追加进展 → 当前认识与待解问题 → 暂停或归档复盘。资料可以属于多个事件，原文仍只保存在 `clips`；删除事件或解除关联绝不删除原收存。 |
| **问** | 只在你收存的东西里找答案。每句都带 `[S-编号]` 出处，点一下跳到原文；没有出处的句子服务端直接丢掉。 |
| **回顾** | 把最近 7 / 30 / 90 天收的东西串成一段：在讲什么、几条主线、哪里还缺证据。 |
| **设置** | AI 状态、库位置、导出。就这些。 |

**网页和文件是两套待遇。**

- **网页链接**：收下时只存标题和地址。要全文点详情页的「抓正文」——那一下才真正去取，取到就存进这条，详情页出现「正文」面板，AI 也才有材料可读。
- **导入的文件**：只存原件，**不抽正文入库**。详情页一个「打开原件」按钮，PDF / 纯文本在浏览器里直接打开，HTML 点「直接读」在观澜内按原版式直读（沙箱隔离、无需下载），其它类型下载；图片会在卡片和详情页直接显示成缩略图，点开看原图。向 AI 提问时，PDF、DOCX、PPTX、XLSX、EPUB 和纯文本会在内存里临时读取一次，读完即弃；扫描版 PDF 没有文字层时需要先 OCR。

## 启动

桌面「观澜」图标就是全部：点一次，服务起来，开**一个**窗口。

桌面有两个入口：「观澜」（`观澜.url` → `launch.vbs`）与「观澜（应用版）」
（`.lnk`），两者都落到打包好的 `dist/观澜/观澜.exe`，同一份代码、同一份数据。

`launch.vbs` 优先找 `dist/` 下的 exe 直接运行（wscript 静默、不弹黑框），
找不到才回退源码形态 `entry.py`；`start.cmd` 同理。这样桌面图标不依赖系统
PATH 里是哪个 Python —— 之前 PATH 命中的是 Python 3.10，没装 pywebview，
窗口角色会 `ModuleNotFoundError: No module named 'webview'`，图标点了没窗口。

桌面入口拉起 `entry.py` / `观澜.exe` 后：

- 服务没起来 → 后台拉起（`pythonw`，日志写 `data/server.log`）
- 等到端口真的能响应 HTTP 才开窗口，不再靠 `timeout 2` 猜
- 已经开着一个观澜窗口 → 直接提到前台，**不再开第二个**
- 窗口只由 `launch.py` 开。`server.py` 发现端口被占用时只打印一行并退出（exit 3），
  不再自己 `webbrowser.open()`——那正是「点一次出两个界面」的根因

命令行：

```bash
start.cmd                 # 同图标，控制台入口（调试用）
start.cmd status          # 看是否在跑
start.cmd stop            # 停掉后台服务

python server.py          # 前台跑，Ctrl+C 停止，日志直接打屏
python server.py --seed   # 首次带示例数据
```

打开 http://127.0.0.1:8790/

### 窗口是自己的，不是浏览器

窗口由 `native_window.py` 用 **pywebview + 系统 WebView2 Runtime** 创建，渲染引擎
作为控件嵌在自己的 WinForms 窗口里：

| | 旧的 `msedge.exe --app` | 现在 |
|---|---|---|
| 主进程 | Edge 浏览器 | 观澜自己（`pythonw native_window.py`） |
| 地址栏 / 标签 / 浏览器菜单 | 藏起来而已 | 没有 |
| `WM_CLOSE` | Chromium 处理 | 自己的 `closing` 事件 |
| 独立浏览器 profile | 一整个 `cache/browser` | `cache/webview2`（纯 ASCII 路径） |

前端 `static/` 一行没改：服务仍是 `127.0.0.1:8790`，窗口只是换了个宿主去加载它。
依赖 `pywebview`（Windows 后端走 `pythonnet` + WinForms），系统需装 WebView2
Runtime（本机已有 Evergreen 157）。安装：`python -m pip install pywebview`。

> `storage_path` 必须是纯 ASCII 目录：WebView2 的 user data folder 遇到中文临时目录会
> 报 `E_ABORT`（本机 `%TEMP%` 带中文用户名）；且窗口要等 `events.shown` 之后才能
> 碰 `native.Handle`，提前访问会让 WebView2 初始化中止。

### 关窗口 ≠ 退出

点右上角 × 走 `closing` 事件 → `ShowWindow(SW_HIDE)` → **返回 False 取消关闭**。
窗口对象、DOM、滚动位置、未提交的输入全部原样保留，服务继续在后台跑：

- 单击托盘图标（或再点一次桌面「观澜」）→ `SW_SHOW` 恢复**同一个 hwnd**，零重载
- 右键托盘 → 「显示观澜」/「隐藏到托盘」/「退出观澜」
- 「退出观澜」和 `start.cmd stop` 才是真退出：写 `.gl-exiting` 放行关闭 + 停服务 + 撤图标

四个角色的进程各司其职：`server.py`（HTTP）、`native_window.py`（窗口）、
`tray.py`（托盘，纯 ctypes Win32，无第三方依赖）、`launch.py`（启动器）。
它们靠 `data/.gl-window-hwnd`、`.gl-exiting` 和窗口消息通信，零轮询。
日志：`data/server.log` / `native.log` / `tray.log`。

回归验证：`python tools/verify_tray.py`；
回滚：`python tools/rollback_native.py`（回到 Edge --app 版本）。
上一轮托盘改造的回滚入口仍保留：`python tools/rollback_tray.py`。

### 打包成 exe（已完成）

四个角色已合并进**单一入口** `entry.py`，靠 `--role` 区分：

```
观澜.exe                            启动器（默认）
观澜.exe --role=server --lan        HTTP 服务
观澜.exe --role=tray                托盘守护
观澜.exe --role=window              WebView2 宿主窗口
观澜.exe --stop / --status          运维
```

子进程统一走 `app_paths.role_cmd()`：源码形态是
`pythonw -u entry.py --role=...`，打包形态是 `观澜.exe --role=...`，
不再去找磁盘上的 `.py`。路径拆成两个：`APP_DIR`（exe 所在目录，数据落盘 /
cwd）与 `RES_DIR`（`sys._MEIPASS`，static / sql / 图标 / DLL），由
`app_paths.py` 统一解析 —— PyInstaller 里 `__file__` 不再是程序目录。

```bash
python -m pip install pyinstaller pywebview
python tools/build_exe.py            # → dist/观澜/观澜.exe + _internal/
python tools/install_shortcut.py     # 桌面新建「观澜（应用版）」
python tools/install_shortcut.py --remove
```

产物是 **onedir**（`观澜.exe` 11 MB + `_internal/` 约 86 MB），双击 exe 即用，
不依赖系统 Python。桌面「观澜」原图标（`观澜.url` → `launch.vbs`）与
「观澜（应用版）」`.lnk` 都优先落到这个 exe；`launch.vbs` / `start.cmd`
在 exe 缺失时才回退源码形态 `entry.py`。
回归验证：`python tools/verify_desktop.py`（模拟双击原图标）。

> 为什么不用 `--onefile`：四个角色进程同时启动，每个都把 41 MiB 解压到
> `%TEMP%`，实测并发时 `ClrLoader.dll` / WebView2 程序集时而缺失，出现
> `0x7e`、白屏或窗口起不来。onedir 把 DLL 固定在 `_internal/`，没有解压、
> 没有临时目录，连续两轮验证均 22 PASS。

打包时踩过并修好的四个坑（都在 `native_window.py` / `guanlan.spec`）：
pythonnet 的 coreclr 缺 `runtimeconfig.json`（改 `netfx` 显式预加载）；
`interop_dll_path` 找不到 `WebView2.Core.dll`（平铺到 `_MEIPASS` 根）；
`win-arm64` 平台目录缺失会让 pywebview 抛异常（平台名兜底）；
以及上面那个 onefile 并发竞态。

回归验证：

```bash

GL_VERIFY_EXE="D:/guanlan/dist/观澜/观澜.exe" \
    python tools/verify_tray.py                  # 打包产物
```

回滚：`python tools/rollback_exe.py`。再往上才是注册表开机自启、
`guanlan://` 协议、MSIX / 安装包 —— 这台机器没有相应工具链，留到以后。

## 手机版

同一套界面，窄屏换了一副骨架：左侧栏收起来，底部换成七个入口（收存 / 问 / 洞察 / 检索 / 判断 / 回顾 / 设置），板块变成一条横滑的胶囊，卡片单列，安全和刘海都留了位。

**怎么让手机连上**

1. 电脑端打开「设置 · 手机访问」：技术评审后这里默认关闭，先明确选择一次「保持关闭」或「打开手机访问」。打开后，地址与六位访问码只在电脑端显示。
2. 手机连**同一个 WiFi**，浏览器打开那个地址（形如 `http://192.168.1.7:8790/`）。
3. 在 POST 表单里输一次码，之后由 HttpOnly / SameSite=Strict 的随机会话令牌记住（一年）；访问码不进 URL，也不再作为长期 cookie。

打开之后可以直接「添加到主屏幕」：iPhone 用 Safari 分享 → 添加到主屏幕；Android 用 Chrome 菜单 → 添加到主屏幕。图标就是那个藏青底、金水波的观澜标记。

**开关与边界**

- `launch.py` 启动时带 `--lan`，端口绑到局域网；`data/lan.json` 现在默认 `enabled:false` / `explicit_choice:false`。**能不能进由设置里那个开关决定**，关掉即时生效，不用重启。
- 关着的时候，非本机请求一律 403，返回一页「手机访问现在是关着的」，不泄露任何内容。
- 开着的时候要码。六位，字母表去掉了 0/O/1/I；单 IP 40 次/小时之外另有全局失败计数与指数退避（重启后仍生效）。
- `127.0.0.1` 永远放行——桌面端的行为一格没变。
- 只在家里、办公室这种可信网络开。咖啡厅的公共 WiFi 别开，别人扫到端口至少能看到一个「要访问码」的页面。
- 访问码存在 `data/lan.json`，重装重启都不变。想换就把那个文件删了重启。

**它是什么，不是什么**

它是**同一个服务的手机界面**，不是独立 App：数据还在电脑那个 sqlite 里，手机只是个显示器加输入框。电脑关机/睡眠，手机就打不开——这是设计，不是缺陷。

也不是可安装的 PWA：Service Worker 要求 HTTPS 或 localhost，局域网 http 起不来。所以 Android 上「添加到主屏幕」得到的是快捷方式（打开时还带浏览器地址栏），iPhone 上则是真正的独立窗口。要完整 standalone 得自己配 HTTPS 证书，不值当。

### Android APK（standalone）

想脱离浏览器，就装 `android-local/dist/guanlan-standalone-2.3.0.apk`：Chaquopy 把整个 Python 服务装进 App，WebView 打开本机端口，数据存在应用私有目录，手机上也能导入 EPUB/PDF、批注、检索。内置当前资料库快照，首次启动即可读；打开后每 5 秒与电脑端做一次局域网增量同步（同一 WiFi，电脑端观澜保持开启），也可改用云同步。平板横屏会自动收起标注栏、手机横屏隐藏底部导航，旋转不重建页面。详见 [`docs/Android-2.3.0.md`](docs/Android-2.3.0.md)。

## 材料分级（权威 / 参考 / 资讯）

信源分级说的是「谁说的」，材料分级说的是「它属于库里的哪一层」——两条正交的轴。新华社一条快讯是 T1，但它属于**资讯**；一篇自媒体长文是 T3，却可能值得进**材料**。

| 级 | 叫法 | 什么进来 | 系统怎么待它 |
|---|---|---|---|
| `canon` | 权威 | 法规、公报、机构报告、论文、一手文件 | 可以当依据；不过期 |
| `ref` | 参考 | 深度报道、专业分析、书摘、你上传的文档 | 可引用，算分析；不过期 |
| `daily` | 资讯 | 每日新闻、快讯、推送、公众号 | 只作时效背景；60 天后可折叠 |
| （空） | 未定 | 还没判的 | 照旧可引用，只是答案里标着「未定」；等你发落 |

**顶部四个题头**：`全部 / 材料 / 资讯 / 未定`，各带条数。`材料` = 权威 + 参考。这是分开的两个视图，不是一个列表加筛子。进了板块，条数只算这个板块（右边会写「只算这个板块」），跟着「板块 · N 条」对得上；不信你看 `GET /api/grades?board=2`。

**收存时只问一次**：收存框里的「材料级」四段控件，默认停在「未定」。系统只在有硬依据时替你填：政府/统计/央行/国际组织/期刊域名 → 权威；你上传的 pdf/docx/txt/md → 参考；其余留空。**宁可漏判也不误判**——自动把一个自媒体文章抬成「权威」，比不判更糟。

**批量定级**：卡片左上角有个勾选框（鼠标扫过才显形），选中若干条后底部浮出一条，一次改成某一级。收资讯是一批一批来的，逐条改没人受得了。

**AI 只建议，不越权**：`AI 看一眼` 会多返回一个 `grade` 建议和一句理由，存成 `grade_hint`，不写进 `grade`。详情页出现一行「AI 建议 资讯：这是一条时效新闻 · 采纳 / 不要」，点「采纳」才算数。

**问库按级分流**：材料块头是 `[S-12] (权威·T0) 标题`。`ASK_SYSTEM` 里写死了「资讯只能作时效背景，不能支撑结论」，服务端对**全引资讯**的句子直接丢弃，和 T3/T4 那套是同一段代码。未定不卡——没判过的东西不该因为没判就答不了。排序上权威 ×1.15、参考 ×1.08，同分时材料压过资讯。

**旧资讯只折叠，不删除**：资讯超过 60 天的，在「资讯」页顶部提示「其中 N 条已过 60 天」，点「收起旧资讯」从列表里隐掉（可再点开）。**没有用 `archived` 字段**——`init_db()` 每次启动都会 `UPDATE clips SET archived=0`，用它做归档活不过一次重启。

**老库回填**：第一次启动时按 `tier` 推一遍（T0/T1→权威，T2→参考，T3/T4→资讯，上传的文档→参考，剩下的按域名猜），用 `PRAGMA user_version` 记一次，之后不再动——你手动清成「未定」的条目不会被再推回去。

## 信源分级（T0–T4）

每条收存可以带一个信源等级，默认空着（未分级），你可以随时补：

| 级 | 叫法 | 什么算 |
|---|---|---|
| T0 | 一手数据 | 原始文件、统计公报、法规原文、当事人原话 |
| T1 | 机构共识 | 官方口径、权威机构报告、大媒体调查 |
| T2 | 专业分析 | 专业媒体、研究者的分析 |
| T3 | 自媒体观点 | 个人评论、公众号、视频 |
| T4 | 传闻未证 | 道听途说、截图、二手转述 |

- 收存框右下角「信源」下拉选，单条详情页随时改；卡片上带 `T0`–`T4` 色标，筛选栏可按等级过滤。
- **它不只是标签**：`问` 的时候材料带等级进上下文，一句话如果只靠 T3/T4 支撑，服务端直接丢掉（旧版 I7「T3/T4 不做证据」原样保留）。全库只有弱信源时它会明说「补一个 T0–T2 的来源再来问」，不会拿传闻给你下结论。
- 「依据」里每条材料也标着等级，一眼看出这个答案站在什么上。

## 收存与研究加工

- 详情页**点一下标题就能改**（就地变输入框，回车存、Esc 退、点别处也存；标题不能空着）。文件名导入的默认标题会自动去掉日期前缀和扩展名、下划线换成空格。

- **板块是抽屉，标签是索引。** 一条剪藏最多进一个板块（政治 / 经济 / 文化 / 社会，默认四个），标签可以有很多个。左侧点板块就只看那个抽屉；删板块时里面的条目退回「未分类」，一条都不会丢。
- **资料库是另一种抽屉。** 见下一节。
- 收存时默认存进你当前正在看的板块（在「全部」里则是未分类），框下面的「存入」那排 chips 点一下能改。单条详情页也能随时换板块。
- 一个输入框吃四种东西：`http(s)` 链接（只取标题）、纯文本（直接存）、图片（插图 / Ctrl+V / 拖进来，和文字收成一条）、文件（点按钮选，或者直接拖进框里）。
- **图片像笔记软件一样直接看**：点「插图」选多张图、Ctrl+V 贴截图，或把纯图片拖进收存框；收下前先显示待收缩略图，收下后在列表卡片和详情页直接铺开，点一下看大图。一条最多 12 张，单张 15MB，支持 PNG / JPG / GIF / WebP。图片原件在 `data/notes`，挂接关系记在 `clip_images`，删除条目时一起清理；「导入文件」也能选 PNG / JPG / GIF / WebP，并作为独立原件在卡片上显示。
- 文件走的是**原始二进制通道** `/api/clips/upload`：不 base64、不塞 JSON，服务端边收边写盘，所以不受请求体大小限制。单文件上限 **200MB**（`GL_MAX_UPLOAD_MB` 可调），上传时有百分比进度。
- 文件一律不抽正文入库，原件存进 `data/uploads`，详情页点「打开原件」看。对文件件按 AI 时，只在这轮请求里从原件临时读取文字（PDF / DOCX / PPTX / XLSX / EPUB / 纯文本），读完即弃，既不落库也不显示。PDF 阅读器随应用放在 `vendor/`，不要求用户另装 `pypdf`；扫描件没有文字层时会明确提示需要 OCR。
- **PDF 正文按版面还原**（`pdf_text.py`）：先按字符坐标把每页还原成行，再找栏缝、去页眉页脚、按行距与缩进切段，最后才接断行——双栏论文不再串栏，双语对照的原文与译文各成一段（不会再出现「1776.中大陆会议」这种粘连）。扫描件与加密件给的是具体原因，不是一句「解析失败」。老条目想用新版重抽：详情页点「重提正文」，或调一次 `POST /api/tools/backfill {"redo":"pdf"}` 批量重抽所有 PDF。
- 网页会保留抓取状态和失败原因，随时重抓；URL 跟踪参数、重复文本、重复文件都会去重，重复收同一篇不会产生两条。默认不抓本机/内网地址，确需自托管时设 `GL_ALLOW_PRIVATE_FETCH=1`。
- **手写内容按 Markdown 排版**：收存框、我的判断、随手记、批注、AI 简介里写的 `#` / `**粗体**` / `- 列表` / `> 引用` / `---` / 代码块 / 表格，存下来就按版式显示，不再把记号原样露出来；正在写的输入框下面会长出一块「预览」，只在真写了记号时出现。标题取第一行，但会把记号摘掉。卡片摘要里也只留干净的句子。
- 标签可留空，留空就用 AI 整理时自动补。搜索覆盖标题、正文、摘要、标签。
- 「收下后 AI 看一眼」默认勾着：存完立刻生成简介和标签（几秒），产出直接进卡片，也进「问」的依据池。不想每次都发内容给模型，把勾去掉就行。
- 单文件上限 200MB，原件在 `data/uploads`，导出的 JSON 不含原件。

## 资料库

板块有两种性格，同一种东西，两种用法：

- **普通板块**是「这一阵在看什么」，随手分堆，随时改。
- **资料库**（`boards.kind = 'archive'`）是「库底」——原件、原始数据、权威原文放一处，别和随手攒的资讯混在一起。左侧栏单独一组，名字前面带 `▣`。

建法有四条路，都改的是同一个字段：

1. 新建时勾「建成资料库」
2. 普通板块的题头点「设为资料库」（反向也有「改成普通板块」）
3. `POST /api/boards {"name": "...", "kind": "archive"}`
4. 旧库升级时列已经在了，不会自己多出板块

**进出**：

- 详情页下拉框里资料库带 `▣` 前缀，选它就是移入；旁边还有一个「存进/移出资料库」的一键按钮，不用翻下拉。
- 列表页勾选多条 → 底部浮条上多了「移到…」，可以整批塞进去，也可以整批退回未分类（那就是移出）。
- 资料库题头上的「收进权威与参考（N）」是整批收：把标成权威 / 参考级的材料一次挪进来，按钮上先告诉你 N 是多少，点了会要一次确认。它只改 `board_id`，条目、标签、正文、判断全都不动。

**长得不一样**：进了资料库，卡片不再显示 AI 简介，改成档案行——原件件显示文件名和大小，网页件显示「正文 N 字 · 已抓下来 / 只存了链接」。看的是「我手上有哪些原始材料」，不是「AI 怎么看」。

接口：`GET /api/boards` 每条带 `kind` 与库内权威/参考条数（`material`）；`POST /api/boards/{id}/collect` 整批收；`POST /api/clips/batch {"action":"move","board":null}` 整批移出。

## 抓正文

网页正文不是收存时抓的，是你点「抓正文」那一下才去取。五道工序：

1. **拿页面**：先确定**出口**——系统代理开着就用它；没开就探 `10809 / 7890 / 1080 …` 这些常见本地端口，哪个通走哪个；都不通才直连。哪个域名上次走通了哪条路会记住（`ROUTE_MEMO`），下次直接走那条。然后静态 HTTP 取一次；碰上一堵「请开 JS / 正在验证」的墙（CloudFront、DataDome 这些挑战页），或者拿回来的是空壳（gov.cn、公众号这类正文靠 JS 注入），就交给本机 Chrome/Edge。浏览器这一层不再「到点交卷」：开一条 **DevTools 协议**连接边等边问，`document.body` 里的段落凑够字数就收，凑不够继续等——慢站不用猜 15 秒够不够，快站也不用陪着等到点；这条路直连打不开就换代理再问一遍。还不行的，才退回固定时钟的两档（`--headless=old --timeout=15s / 32s`）。**每一档渲染出来的 HTML 都先抽一次正文，抽不出来才换下一档**；抽到的是 Chrome 自己的报错页就跳过，最后一档才把「网络层断了」说出来。
2. **解编码**：按 header → utf-8 → gb18030 → big5 各解一次，用「常用字 + 中文标点」密度挑最像人话的那份；已经是乱码的再试一次错层修复（latin-1 还原后重解）。
3. **抽正文**：先看结构化数据——`__NEXT_DATA__`（MarketWatch / 巴伦 / WSJ 这类）、JSON-LD 的 `articleBody`，以及 Arc XP 系站点（歪脑、华盛顿邮报这一脉）的 `Fusion.globalContentConfig`：页面里明写了内容接口的地址和参数，直接问那一个接口，一次拿全段落，不用等前端把整站演一遍。没命中再走 DOM：去脚本/导航/页脚/侧栏，优先 `article`/`main`/公众号容器，否则按文本密度选块；逐段取字，丢掉重复段和「登录 / 责任编辑 / 版权所有」这类样板。
4. **收配图**：正文里的图一起抓下来存进 `data/body/`，按原文位置插回段落之间，图注和署名一起存。候选先按类别名、URL 词根、声明宽高筛掉小图标，下载后再按真实文件头认类型、按实际尺寸二次筛（小于 200×110 的不要）；单张 8MB、一次最多 12 张、六路并发，一张失败不影响别的，文件头不是真图片的一律不落盘。走内容接口的站点（如歪脑）接口里只有头图，那就只收头图。正文重抓时旧图一起删。
5. **AI 校对**（可选）：把抽取结果按 3200 字分段交给模型，只做删残余、接断行，不许改写；某段返回明显变短或结尾被截断，就退回那段的原样。结构化正文和内容接口来的正文本来就是干净段落，这一步会跳过。

拿到的东西至少 200 字、至少两个句子才算数（中英文标点都认——只数「。！？」会把整篇英文报道判成「不像正文」），否则报「抓到的内容不像正文」而不是把垃圾塞进库里。标题只是域名（`www.marketwatch.com` 这种）时，抓成会顺手换成页面真标题。同一页可以反复「重抓正文」。

剩下的失败只有两种，报错也分得清：**网络层就断了**（浏览器都打不开，检查梯子）和**正文是脚本后加载的、等到底也没长出来**。

不给 AI 校对时传 `{"ai": false}`，全程只要一两秒。

## 阅读中心

侧栏顶部切到「阅读中心」就进入独立大板块：书架总览、笔记沉淀、全文检索、知识库归档、阅读统计都在它自己的二级导航里；打开一本书是整屏三栏（目录/书签 · 正文 · 标注/笔记/AI/关联）。
两边的栏都能收起：点栏头的「«」或按 `[` / `]`，宽屏收成左/右边缘的一条竖签，窄屏收成抽屉（`Esc`、点遮罩都收）；收起状态记在本机，下次打开还是原样，正文不会因为折列而丢读到的位置。

- **资料**：PDF、EPUB、MOBI、TXT/MD、DOCX/PPTX/XLSX，以及 MP3/MP4 等音视频，拖进书架即可；也能从已有收存里挑条目加入。EPUB 按 nav/ncx 分章，PDF 按大纲或页组，音视频可粘贴文字稿后获得完整阅读能力。
- **阅读**：EPUB 按原书目录锚点分章、按标题分节（目录里可展开收起，点小节直接跳转），PDF 按大纲或页组分章；上/下章、五色高亮与 Markdown 批注、书签、字号/行距/宽度/纸张可调、续读定位与进度记录。高亮直接写进 `clip_annotations`，回收存详情页同样看得见。
- **检索**：正文、批注、笔记、书签一次搜完（FTS5 trigram + 短词兜底），每条结果都能跳回原书原位置。
- **沉淀**：摘录与笔记可一键汇入知识库生成收存卡片，自动建立正反两条引用；也能关联到收存卡片、正典命题或板块，形成可检索、可回溯的知识网络。
- **AI 伴读**：总结本章 / 解释选中 / 全书提纲 / 翻译 / 提炼要点 / 思考题 / 自由提问 / 整理笔记，复用应用内 `ai_chat()`，**走 WorkBuddy 账号云端额度**，界面会标明模型与实际上下文范围。长章取头/中/尾真实节选并标明字数；全书提问先检索单书片段，引用可跳回原文。全书提纲需手动确认，最多 24 章逐章节选后合并，标注实际覆盖范围；整理笔记只生成对比稿，原稿不被覆盖。请求可取消、防重复，问答按章节在当前会话恢复；最近 6 轮对话限量。缓存按材料哈希失效，用量与延迟仅在实际返回时展示。
- **统计与导出**：17 周阅读热力图、连续天数、累计时长；一键导出含出处、批注、笔记、书签与关联清单的 Markdown。

模块结构、表关系、API 与实现步骤见 [`docs/阅读中心-设计与实现.md`](docs/阅读中心-设计与实现.md)。

## 正文阅读与批注

正文面板是一张安静的双栏纸：左边读字，右边留页边。选中任意一段，浮条上可以直接落高亮，也可以写批注。

- **五种语义色**：重点、论据、疑问、反驳、联想。颜色只在有判断意义的地方出现，不是装饰。
- **高亮与批注是同一件事的两种力度**：只选颜色就是高亮，写一段话就是批注；点已有高亮随时改颜色、补字或删除。
- **右侧页边**按原文顺序列出所有批注，点一条就滚回原文位置；窄屏自动变成正文下方的一张清单。
- **重抓正文不丢批注**：库里存的不只是字符位置，还存原句和前后文；正文重抓后位置漂了，前端会先按原句重新锚定，找不到才明确标成「原文有变」。
- **阅读工具**：字号 90%–130% 可调并记住，底部有阅读进度，桌面和手机都能进「专注阅读」；专注模式只留正文和页边。
- 批注和原句会进入全库检索，结果字段显示为「正文批注」；删除条目时批注一起删，JSON 导出也会带上。
- 单条材料的「问」和「洞察」会看到你的批注，并把它和原文分开标出来；AI 不会把你的判断当成原文事实。

## 检索

侧栏「检索」是一个独立页面，不是列表页那个过滤框。

- 一次搜七个地方：标题、标签、简介、我的话、正文、随手记、正文批注
- 按字段加权排序（标题 ×10、标签 ×6、简介/我的话/正文批注 ×4、随手记 ×3、正文 ×1），命中的词高亮
- 每条结果标「命中 正文 / 标签 / 随手记 / 正文批注」，并给一段带上下文的片段，不是干巴巴一行标题
- 搜得顺手就点「保存这组检索」，下次在页面顶部一点回到同一组结果；不想要了点 chip 上的 ×

## 重遇

首页顶部一条「该重看」，每次三条。

- 选的不是最新，是**最久没碰**：按收存时间取对数，从没打开过的加权 1.8，冷门标签再 ×1.25，正文长的 ×1.15
- 刚收的（小于 2 天）和刚看过的（小于 3 天）不推
- 每条右边写清理由：「收进来 40 天，一次没打开过」「23 天没看了 · 收进来 60 天」
- 打开一次就记一次 `viewed_at`，理由就会变成真的
- 「换一批」换个随机种子重抽；「收起」用 localStorage 记住，不再烦你
- 库里东西还太少或太新时，退化成随机翻，附上所在板块

## 判断

轻量正典：一条材料配一句结论。

- 详情页「我的判断」：写一句话 + 选置信（高/中/低）
- 「加反方材料」搜别的条目，点一下挂成反方，最多 6 条
- 侧栏「判断」页把所有判断按置信度分组，每条带来源链接和反方条目
- 判断为空时保存等于删除；这条材料不值得下结论就别硬写

## 洞察

跟 flomo 的「AI 洞察」同一个思路：不是一个对话框，是**一排视角**。同一批材料，换一副眼镜看，出来的东西完全不同。

| 视角 | 谁的方法 | 它问的问题 |
|---|---|---|
| 默认洞察 | 观澜 | 反复出现的模式是什么，你反复用却没定义的前提是什么 |
| 价值澄清 | 观澜 | 你收什么、在哪类事上花笔墨——反推你真正在意的 |
| 逆向思考 | 芒格 | 假设你的判断整体是错的，什么能一次推翻它们 |
| 二阶思考 | 芒格 | 这条结论成立之后，接下来会发生什么，再接下来呢 |
| 盲点地图 | 观澜 | 库里缺什么：哪类证据一条都没有 |
| 立场漂移 | 观澜 | 同一件事，你的说法什么时候变的 |
| 反方代理 | 观澜 | 替最强的反方说话，不搞平衡 |
| 概念考古 | 观澜 | 你反复用的那几个词，在不同条目里各指什么 |

**范围**：全部 / 最近 30 天 / 最近 90 天 / 某个板块。点顶上的范围胶囊切换。

**它不是「问库」**：问库是「关于一个问题」，一条一条找依据；洞察是「关于整个库」，看结构、看盲点、看你自己。所以洞察不强制引用编号，但要求指到具体条目时写《标题》，标题必须一字不差。

**材料怎么选**（`insight_corpus`）：不是简单取最新。有判断的 +3、有随手记的 +1.6、有简介的 +1.2、正文长的按长度加分、权威/参考 +0.8，再加一点新鲜度；按分数取前 120 条，**再按时间正序排**——这样才能看出立场怎么漂。总量封顶 4 万字。

**结果去哪了**：存进 `ai_outputs`（`kind='insight'`），页面下方「过往洞察」里，点开能重读，右边 `×` 能删。

**规矩写在 prompt 里**：只用给定材料、不虚构条目、每段先判断后依据、至少有一条是你不爱听的、最后必须给一行「下一步：」的动手项。模型偶尔还是会甩 `**粗体**` 出来，前端会转成 `<strong>` 而不是显示星号。

## 标签

标签是这套东西的分拣系统：AI 给的只是初稿，最终由你定。

- **详情页**：标签那一行末尾有「＋ 贴标签」，输入回车即成，逗号能一次贴好几个；每个标签后面一个 `×`，点掉就删。改完立刻生效。
- **按标签检索**：点任意标签（详情页的、列表标签栏的、卡片上的）就到列表，只看贴了这个标签的条目。顶部有「正在按标签看 · ×」，点掉恢复全部。
- 标签能和板块、搜索词、信源等级叠加：标签 × 板块 = 这个抽屉里带这个标签的。
- 频次表：`GET /api/clips/tags`，界面上的标签栏就是它，按条数从多到少排。

## 随手记

每条收存下面都能自己补东西——想法、引文、截图，不限条数。

- 页面右下角一个 **+**，点了就在底部展开输入框，写就行。那个十字是用两条线画的，不是字体里的 `+`——字面框会把符号顶得偏高，粗细也随字号漂。滚到「随手记」那块时它会自动收起（那儿有「＋ 写一条」），窄屏干脆不显示，免得压在正文和「送」上。
- **贴图**：Ctrl+V 直接粘截图；也可以点「插入图片」选文件，或者把图拖进框里
- **挂附件**：点「添加附件」选任意文件——PDF、Word、Excel、Markdown、压缩包都行，一次可以选多个；图片和音频走同一个口，会自动按类型显示成缩略图或播放器
- **录音**：点「录音」直接说——按一下开始、再按一下停，停下自动挂上来，录的时候有计时
- 存下来的一条，右上角有「编辑 / 删除」；图片点开看原图，音频就地播放，旁边有「下载」
- 附件存在 `data/notes/`：图片单张 15MB、音频单段 80MB、其它文件单个 100MB；原始文件名和大小一起记着，下载时名字还是你上传时那个
- **点附件直接看**：Markdown 在应用内按标题、段落、列表、引用、代码块、链接和表格渲染；TXT / LOG / CSV / JSON / XML 作为纯文本展开。
- **PDF** 用随应用自带的 PDF.js 6.5.438（Apache-2.0，许可见 `static/PDFJS-LICENSE.txt`）逐页渲染成画布，不再依赖浏览器内置 PDF 插件；首屏先出 4 页，可继续分批加载，桌面和手机都能滚动阅读。
- **Word（DOCX）** 会解析 `document.xml`，保留标题、段落、粗体/斜体/下划线、外链和表格结构；PPTX / XLSX / EPUB / HTML 抽出可读文字后展示，并明确提示“复杂排版请下载原件”；压缩包、旧版 Office 等不能安全预览的格式仍保留下载入口。
- 预览是只读的，不改附件、不生成副本；顶部始终有「下载原件」，Esc 或右上角 × 关闭；电脑和手机同一套界面。
- 从笔记里删掉附件，磁盘上的文件同步删；没挂到任何一条上的孤儿文件会在下次启动时清掉
- 取消编辑器时，正在录的那段直接丢掉，不会偷偷上传
- 列表卡片上会标「随手记 N」

顺手记下的**文字**也算 AI 的材料：问库、深读、下指令的时候，它会看到你在这一条上补过什么。
音频暂不转写，AI 听不到——它的用处是给你自己回听。

## AI 怎么用

四个动作，各有各的位置：

- **简介（自动）**：收下之后就跑，一条材料 → 80 字以内的简介 + 2–4 个标签，写进卡片。默认开着，勾选框可以关。链接件只有标题可读，摘要会很薄；文件件和手写笔记的摘要才有料。
- **指令（手动，随便说）**：详情页有个输入框，直接跟 AI 说人话——「提炼三条」「这条哪里站不住」「换个立场重写」「对我有什么用」，或者你自己写。下面是四个常用指令的 chips，点一下就跑。不走固定模板，你说什么它做什么。
- **深读（手动）**：chips 里的「结构化深读」→ 摘要 / 要点 / 结论 / 待办 / 标签，存成研究记录。要结构化输出时才用。
- **问**：问题 → 先在收存里按实际文本重合挑材料，再让模型只用这些材料回答，句末挂 `[S-编号]`；引用不存在的句子整句丢弃，只靠 T3/T4 撑的句子也丢。跨板块检索——它不管你东西放在哪个抽屉。
- **回顾**：最近 7 / 30 / 90 天 → 一段连续的话：整体在讲什么、几条主线（带引用）、哪里还缺证据。这是「存了以后有什么用」的那个用处。

没有相关材料时它不会编，只会说「收存里没有相关内容」。这个沉默是设计出来的。

**AI 写的东西不是圣旨。** 每张产出卡右上角有「编辑 / 删除」：编辑就地变 textarea，改成你的话再存（存的是手改版本，AI 原文还留在记录里）；删除就是删，连着问答、回顾的历史记录一起，行尾悬停出现 `×`。简介也能改——详情页「AI 简介」右上角「改一下」。

**上游内容审核拦下来怎么办。** 有些正文（政治、涉案、医疗之类）会在模型前面那层就被平台过滤掉，模型回一句「抱歉，系统检测到…」。这不是应用坏了，也不是你操作错了。处理方式：

- 认得出这是拒答（短、且不是 JSON），**不把它当成 AI 的产出去存**——以前会存成一条「（待修复）」的研究记录，现在不会了。
- 自动退成**节选**再试：1600 字 → 800 字 → 400 字，哪一档过就用哪一档。平台是按「这一坨里有多少敏感内容」判的，短段通常能过。
- 结果会明说「只用了开头 N 字（全文 M 字）」，卡片底下也有一行灰字标着，**不冒充读完了全文**。
- 四个地方都走这套：简介、指令、深读、以及问答类接口。真要完全不受这层限制，只能换一个模型端点（`GL_AI_BASE_URL` / `GL_AI_KEY` 指向别家）。

## 事件专题（桌面端）

- 事件列表支持状态、搜索与最新进展；详情提供时间线、关联资料、当前认识、待解问题和归档总结，可导出 Markdown。

## 数据与备份

主库是 `data/guanlan.db`（SQLite WAL 模式），上传原件在 `data/uploads`。旧库启动时只做追加列和新表迁移，不改写原有条目。

**完整备份：先停止服务，再复制整个 `data` 目录。** WAL 运行期间只复制 `.db` 文件可能漏掉未合并内容；在线备份应使用 SQLite backup API。升级前的在线备份已保存为 `data/guanlan.pre-improvement.bak`。

服务没有账号体系；桌面启动器为保留手机访问开关仍可绑局域网地址，但 `LAN_OPEN` 默认 False，非本机请求一律 403。不要把 `GL_BIND` / `PORT` 暴露到不受信任网络；AI 密钥只通过环境变量配置，不写入页面或研究记录。
